# apps/marketing/src/lib/tools

One line per module: what it reads, what it returns, where it sits. Update the line when the file's header comment changes.

- `content-brief-v2-handoff.ts`, `.test.ts` — explicit version-2 confirmed envelope in the existing one-time sessionStorage slot; bounded synchronous staging, exact async parser/TTL and owned-payload cleanup; no document in URL or server persistence.
- `content-draft-v2-language.ts`, `.test.ts` — validates supported BCP-47 tags against the existing language set, returns base adapter code and exact locale without changing the confirmed document.
- `content-draft-v2-prompts.ts` — confirmed H2/H3, section-scoped evidence and approved intent/format/exclusions/navigation guidance; guidance never expands factual references and related links are not embedded by the model.
- `content-draft-v2-llm.ts`, `.test.ts` — CONTENT_DRAFT-only section generation, exact 96 KiB prompt cap, bounded invalid-content retry, truthful token receipts and locale-aware coverage; all network replies in tests are offline seams.
- `content-draft-v2-run.ts`, `.test.ts` — at most three section workers, whole-result coverage, bounded receipt-aware deadlines and exact full-previous section rerun; no missing usage fabrication or publication.
- `content-draft-handler.ts`, `.test.ts` version negotiation — confirmed SEO v2/v3 selects its exact run/section pipeline while SEO v1 and shared GEO v1.1 retain theirs; byte-counted requests copy URL/method/headers/signal without passing Next's request proxy into the native constructor. GEO owned receipts are reverified before quota/provider work, and its original wire cap remains before private verification despite the larger v2 envelope. Legacy reports and unconfirmed v2/v3 are not coerced.

- `content-brief-research-extract.ts` — v2 local Cheerio extraction from already-fetched HTML: iterative main/article/body traversal, scoped template/navigation removal, bounded heading/body segments and full observed main-text measurement. No fetch, model call or HTML rendering; explicit omitted/truncated counts; no whitespace-language gate.
- `content-brief-research-extract.test.ts` — fixed HTML oracles, including ordinary div/span text, no-heading Chinese, nested templates, 10,000-level DOM/heading depth, code-point limits and observed-length/cap accounting.
- `content-brief-v2-crawl.ts`, `.test.ts` — one bounded public-HTTP read per C/T target, raw-body hash and v2 extraction, shared owned-page identity with per-hop/final redirect checks; known structural reCAPTCHA interstitials fail as insufficient evidence, without bypass or rejection of ordinary articles quoting their copy.
- `content-brief-v2-prompts.ts`, `.test.ts` — one complete writing-plan prompt over untrusted data; retain all evidence that fits 48 KiB, use fair relevance-based page sampling only above that cap, preserve every observed page and original counters. V3 receives actual SERP planning context and section-owned questions; GSC query matches do not imply page-purpose matches, and every gap source must be a competitor.
- `content-brief-v2-llm.ts`, `.test.ts` — existing CONTENT_BRIEF configuration and one 30-second maximum attempt within the remaining 45-second run/5-second envelope; exact Luna deployment opts into verified reasoning-none while other models keep defaults. V2 flat and V3 nested model protocols both pass strict full-output validation; no retries, source calls or unknown-token fabrication.
- `content-brief-v3-model.ts`, `.test.ts` — strict private section-owned-question protocol; derives Q/outline mappings from containment then delegates all source/claim/page-plan checks to the existing validator. No dropped invalid items, guessed references or flat fallback; public result schemas are unchanged.
- `keyword-llm-client.ts`, `.test.ts` — shared deadline/usage-safe JSON transport with optional explicit reasoning-none; omitted options preserve prior wire bytes and invalid options fail before fetch. No environment or model-name auto-selection in the transport.
- `content-brief-v2-run.ts`, `.test.ts` — generation after caller admission: parallel source callbacks/SERP, one shared competitor/owned crawl, PAA research, one model assembly, whole-brief self-check. Offline provider seams exercise the real adapters/extractor/parser; this module is not a public route or proof of live provider quality.
- `content-brief-handler.ts` v2/v3 negotiation — explicit `response_schema` selects the new runner and exact requested output version; v3 freezes actual sampled SERP rows/read metadata, v2 forbids invented snapshots, and omitted/v1 retains historical behavior. Shared auth/quota/GSC-subject gates precede provider work; one run-start GSC window, exact profile snapshot, 32-fact cap and all requested GSC loss states are preserved.
- `content-brief-v2-observations.ts`, `.test.ts` — model-independent complete-body length quantiles grouped by unit, distinct-competitor question denominator and v3 sampled SERP format distribution; v2 uses an explicit URL-only retained-page fallback. Unknowns/duplicates/read gaps remain visible; no ranking targets or model-intent claims.
- `content-brief-serp.ts` v2 opt-in — `includePeopleAlsoAsk: true` retains the same response's independent PAA status/text/counts, including PAA-only responses. Defaults/false preserve the legacy request and return shape; no extra request or click-depth parameter. `content-brief-serp.test.ts` pins the compatible behavior and failure paths.

- `gsc-properties-handler.ts` — same-origin authenticated, feature-flagged property refresh. Shares the GSC in-flight slot but uses its own durable 30/IP/hour quota bucket; admission precedes grant renewal and site-list calls. Returns only cookie-bounded properties, real total and brand candidates, with private no-store stable errors and no credentials.
- `gsc-properties-handler.test.ts` — property refresh response, empty/truncated lists, no token leakage, cross-origin and identity refusals, independent durable quota, shared in-flight refusal, unavailable/revoked error mapping and release on every admitted exit.
- `traffic-drop-session.ts` / `traffic-drop-session.test.ts` — page-safe cookie reads plus API-only grant resolution; explicit refresh options reach the grant reader while ordinary tool runs retain their renewal behavior.
- `../auth/grant-cookie.ts` / `../auth/grant-cookie.test.ts` — account-bound grant renewal and explicit property refresh, including unexpired/legacy access tokens, one re-list after renewal, fail-closed freshness, preserved session on temporary errors and cookie-budget-matched property responses.

- `content-brief-serp.ts` — `readContentBriefSerp({ keyword, market, language, signal })`: the Content Brief Builder's only paid SERP read. One `serpOrganic` call at `SERP_DEPTH`, rows returned verbatim (rank / url / domain / title), `reads: SerpReadMeta` by count (complete / partial when returned < depth or the provider's `unresolvedItemCount` > 0, carried as `unresolved` / insufficient_evidence when nothing came back / provider_error when rows came back but every one was unresolved, or on any thrown error / timeout), cost through `onCost` plus one `[content-brief] paid_call` log line. Throws only `ContentBriefSerpInputError` (`unsupported_market` / `unsupported_language`) before any request. Deliberately not `readSerpLandscape`, which drops url/title and buys a Labs call.
- `content-brief-crawl.ts` — `crawlContentBriefTargets({ targets, deadlineAt, language })`: cross-host fetch of the deduplicated SERP URLs via `fetchPublicResource` (no `openCrawlGate`, no `crawl-cache`), `CRAWL_CONCURRENCY` in flight, each fetch raced against its timeout + `CRAWL_TEARDOWN_GRACE_MS` so a hung dispatcher close cannot pin a slot, wall clock = min(now + `CRAWL_DEADLINE_MS`, deadlineAt − `ENVELOPE_MS`); unstarted URLs become `failed/timeout`. Each page parses into a `CrawlObservation` (`C<n>` matching `S<n>`, h2/h3 via `contextPageHeadings` capped at `CRAWL_HEADINGS_PER_PAGE_MAX` per level, per-heading excerpts split at every h2/h3, sha256 of the prose, `word_count` null when truncated or non-whitespace-tokenised) or a `CrawlFailure` (timeout / provider_error with the `PublicResourceErrorCode` or `http_<status>` for a non-2xx page / validation_failed when the exact media type is neither `text/html` nor `application/xhtml+xml`).
- `content-brief-llm.ts` — `resolveContentBriefLlmConfig(env)` / `resolveContentDraftLlmConfig(env)` read only the `CONTENT_BRIEF_*` / `CONTENT_DRAFT_*` sets (null when key or model is missing; no fallback to `KEYWORD_MAP_*`, Azure or `OPENAI_*`). `runContentBriefLlm(input, deps)` is the brief's single model call: timeout = min(`LLM_DEADLINE_MS`, deadlineAt − now − `ENVELOPE_MS`), `maxOutputTokens` = `LLM_MAX_OUTPUT_TOKENS`, temperature `CONTENT_BRIEF_LLM_TEMPERATURE`; returns `{ output: ModelBriefOutput | null, reads: LlmReadMeta, derived_from }`. Nothing to ask (no questions, no facts, no pages) returns `insufficient_evidence` without a call. Every failure is a `reads` branch (`not_configured` / `timeout` / `provider_error` / `validation_failed`, tokens and calls kept), never a throw; `parseModelBriefOutput` cleans free text through the shared `boundedModelText` decoder and rejects unknown or repeated Q/C/P/G ids (including a `page_ref` repeated within a list), cap overruns (`OUTLINE_CAP` / `INTERNAL_LINKS_CAP` / `DO_NOT_COVER_CAP`, `QUESTION_MAX_CHARS` / `MODEL_TEXT_MAX_CHARS`), an outline that does not answer every input Q exactly once, a `checked_against` set that is not exactly `observedIds`, and any field that should have been null.
- `content-brief-llm.test.ts` — fake client + fixed clock + injected env: config resolution and non-fallback, each `reads` branch, request shape, `temperature_effective` pin vs null, `derived_from` for all four feed combinations, and one counter-example per validation rule.
- `content-brief-prompts.ts` — `buildContentBriefSystemPrompt()` / `buildContentBriefUserPrompt(input)`: competitor heading clusters + excerpts, every observed page's H2s (`observedPages`, the set `checked_against` is measured against), profile facts and GSC page rows are `sanitizeForPrompt`-stripped and sealed in `SITE_CONTENT_*`, keywords in `SEED_TERMS_*`; the schema block prints `MODEL_BRIEF_OUTPUT_KEYS` (the same constant the parser checks), the three caps and the three must-be-null rules. Prompt text only — no call, no parse.
- `content-brief-prompts.test.ts` — injected `</site_content> …` heading cannot close the block; every `ModelBriefOutput` key is in the schema block; caps, null rules, per-page excerpt and supporting-keyword bounds are pinned inside their sentences.
- `content-brief-handler.ts` — `handleContentBriefRequest(request, deps)`: the Content Brief Builder's only orchestration. Admission before any paid call (Supabase login → per-account slot → account / IP / daily quota buckets via `consumePublicToolQuota`), one `deadlineAt`, SERP + profile in parallel, host-deduped crawl as soon as SERP is back, local derivation, one LLM call, `assembleContentBrief`; one JSON log line per run. With a chosen property the GSC lane (session → shared gate once → grant → query / query×page / page reads over `coverageWindow`) feeds `computeVerdict` and the G* page ledger; without one the verdict is `undecidable/no_gsc_property`. Every emitted brief must pass `parseContentBrief`; a model answer that breaks it is dropped as `validation_failed`, anything else is `brief_unavailable`. `parseContentBriefRequest` and `profileFacts` (deterministic P* from `MarketingWebsiteProfileV1`, inferred → model provenance) are exported for tests.
- `tool-handoff.ts` — fixed-key, ten-minute, one-use connected-tool navigation. Daily Search Briefing and Competitor Gap retain their exact property/query/page scopes and destinations; Content Draft carries a safe published URL, its question, market and brief fingerprint with `property:null`. SEO drafts go to On-Page; GEO drafts go to Page Citability. Unknown/expired/malformed/wrong-destination envelopes fail closed. Same-origin new-tab links use `TOOL_HANDOFF_LINK_PROPS`; this is not authority for server-owned GEO observations.
- `tool-handoff.test.ts` — write / consume / one-time / TTL / wrong-destination per source; per-field rejection sweeps built from each fixture's keys; the content-draft cases pin null-property, fingerprint shape, page-not-bound, and that the null never loosens the other two sources.
- `content-brief-constants-alignment.test.ts` — app-side pins the package cannot express: `GSC_LOOKBACK_DAYS === COVERAGE_WINDOW_DAYS`, crawl timeout = public fetch default, budget arithmetic under the route's `maxDuration`, section byte sizing, non-whitespace languages ⊆ SERP languages.
- `content-draft-llm.ts` — the Content Draft Writer's only model calls, config from `resolveContentDraftLlmConfig` (`CONTENT_DRAFT_*` only; `deps.config: null` = not configured, no call). `generateDraftSection(input, deps)`: one call per requested H2 at `CONTENT_DRAFT_LLM_TEMPERATURE` (0.4; a deployment pin overrides it and is reported as `temperature_effective`), `maxOutputTokens` = `SECTION_MAX_OUTPUT_TOKENS`, timeout = min(`SECTION_TIMEOUT_MS`, deadlineAt − now − `ENVELOPE_MS`); the reply is shape-parsed into `ModelSectionOutput` (`parseModelSectionShape`: exact keys, ≥ 1 paragraph, ≥ 1 sentence each, closed claim) and judged only by `validateSectionOutput` with citable ids = pages that carried an excerpt; a rejected reply is asked for once more with the rule and path prepended (`SECTION_MAX_ATTEMPTS`), a second rejection is `validation_failed`, and no claim is ever rewritten. Transport failures and deadlines are not retried (`timeout` / `provider_error` / `not_configured`); `attempts` counts every request that left the process (a timed-out or refused request is one attempt), and tokens are a strict sum over those attempts — any one reporting no usage makes the section's `input_tokens` / `output_tokens` null (the shared `mergeKeywordLlmUsage`, which absorbs null, is deliberately not used); `validateSectionOutput` gets `stanceAllowed = gapAngle !== null`, so a `stance` outside the gap-angle section is `validation_failed`; a non-`KeywordLlmError` is rethrown, and a `language` outside `LANGUAGE_NAMES` throws `RangeError` before any call (the handler validates `language ∈ SERP_LANGUAGES` first). `runDraftCoverage(input, deps)`: one fresh-context call at temperature 0 (`CONTENT_DRAFT_COVERAGE_TEMPERATURE`), `COVERAGE_MAX_OUTPUT_TOKENS` / `COVERAGE_TIMEOUT_MS`, no retry; returns `{ items: ModelCoverageOutput["items"] | null, reads: LlmReadMeta }` where `items` is shape-checked only (`parseModelCoverageShape`, `gap` cleaned by `boundedModelText`) — `validateCoverageOutput(items, askable, okSectionIds)` is the handler's call; an empty question list returns `items: []` without a call (`insufficient_evidence`); `reads.calls` is 1 for any request sent, answered or not, and 0 only when nothing was sent.
- `content-draft-llm.test.ts` — fake client with ordered replies + fixed clock + injected env: every section fail branch (not_configured / pre-call timeout / client timeout / each provider reason / schema_invalid / rethrow), retry semantics (rejected twice → `validation_failed` with attempts 2 and summed tokens; rejected once then ok → attempts 2 and the retry prompt names the rule; no budget for the retry → attempts 1; billed rejection + timed-out retry → attempts 2 with null tokens; two billed attempts → strict sum), `stance_outside_gap_angle` when `gapAngle` is null, uncitable C* and unknown P* refusals, support_count / word_count derivation, pin vs null `temperature_effective`, model id fallback, `RangeError` on an out-of-table language before any call; coverage: no-question short-circuit, each read branch with `calls: 1` for every sent request (timeout / 429 / network / billed-but-empty), temperature 0 and fresh context, non-JSON → `validation_failed`, shape-valid reply returned untouched, decoder cleaning, `RangeError` on language; one counter-example per shape rule for both parsers.
- `content-draft-prompts.ts` — `buildDraftSectionSystemPrompt()` (handoff §5.3's six claim rules, "evidence is only the excerpts", `SECTION_MAX_SENTENCES` / `SENTENCE_MAX_CHARS`, `CLAIM_STATES`) / `buildDraftSectionUserPrompt(input, rejection?)` (section headings, questions with member headings, competitor pages with excerpts — a page without one is printed as uncitable — profile facts with derivation and an inferred-fact note that reads "stance only" on the gap-angle section and "cannot be cited" elsewhere, the GAP ANGLE block only when mounted and otherwise a one-line `STANCE: … no sentence may be "stance"` prohibition (system rule 3 says the same: stance only in the section carrying a GAP ANGLE block), tone / person / product-mention style lines, `MODEL_SECTION_OUTPUT_KEYS` schema with word placeholders); `buildDraftCoverageSystemPrompt()` / `buildDraftCoverageUserPrompt(input)` (handoff §5.4 scope only: `[section id=O*]` + text sealed at `SECTION_TEXT_MAX_CHARS` so a validated section is never truncated, and `question_id` + `q` — no keyword, no `h2`, no seed block; three statuses explained with `none` declared expected, `MODEL_COVERAGE_OUTPUT_KEYS` schema with one example per status including a `none`). Every third-party, model and visitor string is `sanitizeForPrompt`-stripped and sealed in `SITE_CONTENT_*` / `SEED_TERMS_*`; the language is never interpolated — `languageName(code)` reads the closed `LANGUAGE_NAMES` table (one English name per `SERP_LANGUAGES` code) and throws `RangeError` otherwise. Prompt text only — no call, no parse.
- `content-draft-prompts.test.ts` — injected `</site_content> … </seed_terms>` in every field cannot close a block and block counts stay balanced; the six rules, evidence rule and caps are pinned inside their sentences; every output key and claim state is in the schema block with no id-shaped placeholder; inferred fact annotation in both branches, no-facts branch, no-gap-angle branch where every remaining `"stance"` line is a prohibition, the rule-3 restriction pinned, uncitable page line, per-page excerpt bound, all nine settings phrasings, language name line, retry prefix; `LANGUAGE_NAMES` keys pinned to `SERP_LANGUAGES` in both directions and eight rejected codes (including an instruction disguised as a code); coverage: `none` example line, fresh context (no section rules), no keyword / no heading / no seed block, longest validated section survives intact.
- `content-draft-handler.ts` — the shared SEO/GEO run and whole-result section-rerun endpoints. Authenticate and acquire the account slot; GEO parses and resolves exact owner-scoped KB/Profile/run receipts, then checks the owned question under a five-second preflight before quota/provider work; expected question-quality refusals return actionable 422 without a charge. SEO keeps its existing bucket/parse order. One request deadline bounds generation and coverage; every started generation is drained before releasing the slot. GEO section input carries eligible literal fact receipts plus explicit missing dimensions, never AI sampled answers as facts. Every emitted result is reparsed with actual lineage/coverage metadata; outages return closed unavailable states and unsupported facts never become verified KB sentences.
- `content-draft-handler.test.ts` — admission order (slot / bucket refusals come before a bad brief is parsed), per-bucket keys and limits, closed market / language, duplicate section ids, pre-slot exceptions, deadline propagation, per-section page scope, facts / gap-angle routing per product_mention, skipped ordering, one-section failure keeps the rest and feeds heuristic coverage, coverage-unavailable, self-check refusal (foreign page, borrowed page), drain-before-release on throw; section rerun whole-result contract, edited / foreign / missing previous result, wrong brief, skipped-section write, unknown id.

- `content-brief-handoff.ts` — shared Brief → Draft one-use handoff with fixed key, exact TTL and byte limit. The consumer explicitly distinguishes strict legacy SEO v1 and GEO v1.1, preserving origin/evidence bytes; an import fingerprint is consistency, not authentication. Storage failure/oversize refuses navigation; actual GEO evidence is re-resolved by the Draft server before quota/provider work.
- `content-brief-handoff.test.ts` — envelope shape and TTL pin, round-trip through `parseContentBriefHandoff`, over-cap refusal without a write, storage failure reported, one-shot take.
- `content-draft-messages.test.ts` — `tools.contentDraft.*` coverage of every draft-side closed code (`errors` incl. `draft_unavailable` + `unknown`, `sectionFail`, `coverageCause`, `coverageStatus`, `verifyKind(Body)`, `claims(Body)`, `modes` / `modeBody`, `unavailable`, settings options) in EN and ZH, the bare-keyword and single-source phrases, and EN/ZH structural parity.
- `content-draft-copy-honesty.test.ts` — every draft threshold the page prints (`CONTENT_BRIEF_HANDOFF_MAX_BYTES`, `SECTION_TIMEOUT_MS`, `DRAFT_TOTAL_BUDGET_MS`, `SECTION_ENDPOINT_BUDGET_MS`, `SECTION_RERUN_SOFT_MAX`, `SECTION_MAX_ATTEMPTS`) is interpolated, never a digit in the template; constant arithmetic (section budget < draft budget, section request > draft request, rerun soft cap ≤ hourly section quota, retries fit the endpoint budget).
