# apps/marketing/src/lib/task-center

Server code for the task center (short-drama promotion tasks), My Earnings, and the admin backend that uploads clips. Task data lives in TencentDB (`TASKS_DATABASE_URL`), files in a private Cloudflare R2 bucket, sign-in stays on Supabase. With either one unset, every page and route says it is unavailable instead of failing, which is what keeps the Vercel rollback build working. Modules here import each other by relative path so the tests can load them.

- `db.ts` — the lazy `pg` pool (null when `TASKS_DATABASE_URL` is unset), `withTransaction`, and safe bigint-to-number reads.
- `contracts.ts` — claim channels (`all` for new claims), account platforms and statuses, drama statuses, audiences (女频/男频), clip types, the genre slug (male/female and the like refused: they are an audience) with suggested genres, upload types and size limits, the promo code alphabet, the platforms and languages 查剧 can ask 选剧台 about and which of them it also reads from their own site, the platform drama id shape (letters, digits, `_`, `-`, or GoodShort's base64), tags, and the zod inputs for every admin and claim request (the platform link optional, blank meaning none, only a full https URL).
- `dramas-store.ts` — the 素材广场 listing (every ready clip of every published drama, filtered by platform, language, audience, genre and clip type, searched literally, sorted, paged, with 本周爆款 worked out per read: the top 3 published dramas by distinct claimants in the last 7 days, at least one claim) and its filter facets; what each listed drama's dialog adds (synopsis and its ready clips in order; never the platform's URL); the reader's drama page every promo link opens (any drama ever listed, so a take-down never breaks a posted link; a draft has none): title, chips, cover, synopsis, the trailer-tagged video or else the first ready one, and only whether a platform link exists, never the URL; a drama's detail with its ready assets; the admin reads; create, update, status, cover and asset writes, the clip retag and rename (either alone leaves the other), and the clip's still (a retried completion keeps the one already recorded; delete hands back both keys). Replaced cover files are kept in R2, so a retried upload can never leave a drama on a deleted image. Each drama may have one platform link (`promo_target_url`, https; optional since 0006): where the page's 去看全集 goes. Every drama carries its tags; an edit that leaves them out keeps them. A drama imported from 查剧 is inserted once per platform drama id (a second import gets the first one's id back), with 频道 and genre when the theater's page gave them, and `listedBySource` tells 查剧 which results are already here.
- `claims-store.ts` — idempotent claim of one code per user, drama and channel (new claims are always channel `all`, so one code and one link per drama; a code collision retries with a new code); a user's claims with their clicks; `/t/<code>` recording one click and naming the drama whose page it opens (any claimed code, even after a take-down); and 去看全集's target, the drama's platform link with the code added as its sub-channel parameter only when that code was claimed for that same drama, so a `ref` copied onto another drama's page earns nothing; a sub-channel value stored in the platform link is replaced by that code, or dropped without one. That hop records no click. The redirect URL is always built through `URL`, so a target with non-ASCII characters still makes a valid ASCII `Location`.
- `accounts-store.ts` — accounts submitted for whitelisting: submit (a handle already on file returns that row unchanged, so a resubmission never resets a review; at most 20 per person), the promoter's list, withdraw (only while waiting, so a rejection cannot be wiped by deleting and resubmitting), a per-user advisory lock so concurrent submissions cannot pass the cap, the admin list with waiting accounts first, and the review write.
- `earnings-store.ts` — all-or-nothing settlement import (any unknown code rejects the whole file), the import history, and a user's totals per currency and per platform; a figure the platform did not give stays null and shows as "—". Sums come back as decimal strings (`::text`), so they never round or overflow a JS number, each with a flag saying whether some rows in it lacked that figure; the page marks those "partial". A day missing from every file is not detected.
- `settlement-csv.ts` — the settlement CSV: English or Chinese headers, BOM and CRLF, quoted fields, per-line problems, duplicate code+day rows refused; anything that could be read two ways refused too (a row wider than the header even when the overflow is empty, text after a closing quote, two columns meaning the same thing); a 2 MB limit counted in UTF-8 bytes; and amounts converted to minor units by the currency's own exponent without floating point.
- `drama-lookup.ts` — the client for pick-workbench's read-only `/api/pick/lookup/drama/` (`PICK_LOOKUP_URL`, `PICK_LOOKUP_TOKEN`; 90 s, under Cloudflare's cut-off; for ReelShort, StardustTV, MoboReels and NetShort 选剧台 answers from its own 剧库 when it can, with 完结 unknown and no synopsis, cover or tags): reads only well-formed rows, tells a query that will never work from one to retry, fits a 北斗 row to the dramas table with the theater's own page taking over field by field (title, episodes, pay start, synopsis, tags, 频道, genre, and the page's drama id so 北斗's two ids for one drama list it once; 中文名 and 完结 stay 北斗's; out-of-range counts become unknown, text trimmed, tags deduplicated, no language means hand entry), and fetches the cover the page or 北斗 gave from a public https host only, as JPEG/PNG/WebP up to 20 MB, never logging its URL.
- `theater-details.ts` — 查剧's second step: which platforms have a reader, the drama as the theater's own site shows it (null when there is no reader, the id is not that platform's, or the site could not be read), and the link to a drama's page there.
