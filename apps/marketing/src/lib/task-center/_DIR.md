# apps/marketing/src/lib/task-center

Server code for the task center (short-drama promotion tasks), My Earnings, and the admin backend that uploads clips. Task data lives in TencentDB (`TASKS_DATABASE_URL`), files in a private Cloudflare R2 bucket, sign-in stays on Supabase. With either one unset, every page and route says it is unavailable instead of failing, which is what keeps the Vercel rollback build working. Modules here import each other by relative path so the tests can load them.

- `db.ts` — the lazy `pg` pool (null when `TASKS_DATABASE_URL` is unset), `withTransaction`, and safe bigint-to-number reads.
- `contracts.ts` — claim channels (`all` for new claims), account platforms and statuses, drama statuses, audiences (女频/男频), clip types, the genre slug (male/female and the like refused: they are an audience) with suggested genres, upload types and size limits, the promo code alphabet, the platforms and languages 查剧 can ask 选剧台 about and which of them it also reads from their own site, the platform drama id shape (letters, digits, `_`, `-`, or GoodShort's base64), tags, and the zod inputs for every admin and claim request (the platform link optional, blank meaning none, only a full https URL).
- `dramas-store.ts` — the 素材广场 listing (one card per published drama with a matching ready clip, fronted by its first matching clip in 系列资源 order, carrying the drama's ready clip count, dramas ordered by their newest upload and counted as dramas; filtered by platform, language, audience, genre, a tag (any part of one, in any case, `%` and `_` taken literally) and clip type, searched literally, sorted, paged, with 本周爆款 worked out per read: the top 3 published dramas by distinct claimants in the last 7 days, at least one claim) and its filter facets (platforms, languages, genres, and the tags of published dramas, each once; a drama without tags still counts for the rest); what each listed drama's dialog adds (synopsis and its ready clips in order, each with its kind, type and still key; never the platform's URL); the reader's drama page every promo link opens (any drama ever listed, so a take-down never breaks a posted link; a draft has none): title, chips, cover, synopsis, the trailer-tagged video or else the first ready one, and only whether a platform link exists, never the URL; a drama's detail with its ready assets; the admin reads; create, update, status, cover and asset writes, the clip retag and rename (either alone leaves the other), and the clip's still (a retried completion keeps the one already recorded; delete hands back both keys). Replaced cover files are kept in R2, so a retried upload can never leave a drama on a deleted image. Each drama may have one platform link (`promo_target_url`, https; optional since 0006): where the page's 去看全集 goes. Every drama carries its tags, which the 标签 filter searches; an edit that leaves them out keeps them. A drama imported from 查剧 is inserted once per platform drama id (a second import gets the first one's id back), with 频道 and genre when the theater's page gave them, and `listedBySource` tells 查剧 which results are already here. `refillDrama` (从官网补全) writes what 查剧 finds now over a drama already listed: what the source knows replaces the drama's, what it leaves out (an empty tag list included) stays; title, platform, language, status, cover and platform link never change; the first paid episode is dropped when the new episode count no longer has it; the drama takes the source's id only when it has none, and another drama holding that id refuses it as a second listing.
- `claims-store.ts` — idempotent claim of one code per user, drama and channel (new claims are always channel `all`, so one code per drama, behind both of its links; a code collision retries with a new code); a user's claims with their clicks; `/t/<code>` and `/t/<code>/go` recording one click and naming the drama the code is for (any claimed code, even after a take-down); and the platform target of 去看全集 and of `/t/<code>/go`, the drama's platform link with the code added as its sub-channel parameter only when that code was claimed for that same drama, so a `ref` copied onto another drama's page earns nothing; a sub-channel value stored in the platform link is replaced by that code, or dropped without one. The 去看全集 hop records no click; `/t/<code>/go` has already recorded its one. The redirect URL is always built through `URL`, so a target with non-ASCII characters still makes a valid ASCII `Location`.
- `accounts-store.ts` — accounts submitted for whitelisting: submit (a handle already on file returns that row unchanged, so a resubmission never resets a review; at most 20 per person), the promoter's list, withdraw (only while waiting, so a rejection cannot be wiped by deleting and resubmitting), a per-user advisory lock so concurrent submissions cannot pass the cap, the admin list with waiting accounts first, and the review write.
- `earnings-store.ts` — all-or-nothing settlement import (any unknown code rejects the whole file), the import history, and a user's totals per currency and per platform; a figure the platform did not give stays null and shows as "—". Sums come back as decimal strings (`::text`), so they never round or overflow a JS number, each with a flag saying whether some rows in it lacked that figure; the page marks those "partial". A day missing from every file is not detected.
- `settlement-csv.ts` — the settlement CSV: English or Chinese headers, BOM and CRLF, quoted fields, per-line problems, duplicate code+day rows refused; anything that could be read two ways refused too (a row wider than the header even when the overflow is empty, text after a closing quote, two columns meaning the same thing); a 2 MB limit counted in UTF-8 bytes; and amounts converted to minor units by the currency's own exponent without floating point.
- `drama-lookup.ts` — the client for pick-workbench's read-only `/api/pick/lookup/drama/` (`PICK_LOOKUP_URL`, `PICK_LOOKUP_TOKEN`; 90 s, under Cloudflare's cut-off; for ReelShort, StardustTV, MoboReels and NetShort 选剧台 answers from its own 剧库 when it can, with 完结 unknown and no synopsis, cover or tags): reads only well-formed rows, tells a query that will never work from one to retry, finds which row a drama already listed is (`pickMatch`: by its platform id when it has one, else by its exact title, case, curly quotes and spacing aside; never a near title, never a guess between two), fits a 北斗 row to the dramas table with the theater's own page taking over field by field (title, episodes, pay start, synopsis, tags, 频道, genre, and the page's drama id so 北斗's two ids for one drama list it once; 中文名 and 完结 stay 北斗's; out-of-range counts become unknown, text trimmed, tags deduplicated, no language means hand entry), and fetches the cover the page or 北斗 gave from a public https host only, as JPEG/PNG/WebP up to 20 MB, never logging its URL.
- `drama-cover.ts` — copies the cover 查剧 found (北斗's or the theater's CDN) into R2 and sets it on the drama, within the time the admin request has left: saved, missing (no URL) or failed (the operator then uploads one). Shared by 用这部 and 从官网补全.
- `theater-details.ts` — 查剧's second step: which platforms have a reader, the drama as the theater's own site shows it (null when there is no reader, the id is not that platform's, or the site could not be read), and the link to a drama's page there. Read: ReelShort, StardustTV, MoboReels, NetShort, YourChannel. Linked only: DramaBox, whose CloudFront answers the production server 403. No reader: KalosTV and FlareFlow (signed, encrypted API), GoodShort (北斗's base64 id is not the site's, and its API refuses the production server), ShortMax and FlickReels (nothing in 北斗).
- `theater-http.ts` — the one network door for the readers: only the theater's own https hosts, at most three redirects (none for a POST), only the expected text/html or JSON, up to 2 MB, one deadline per import (an answer parsed after it is dropped), never throws; plus the field readers every parser shares (`htmlText` reads a description sent as HTML as plain paragraphs, entities decoded, and leaves out everything from the first heading on when there is story before it), a data-script finder that reads the page in one pass (no regex a hostile page can make quadratic), a cap of 60 tags read per page, the language normalizer (`en_US` → `en`, traditional Chinese → `zh-TW`) and the genre slug. No runtime imports, so a reader runs on its own under node's type stripping.
- `theater-reelshort.ts` — ReelShort's page (`__NEXT_DATA__`): the synopsis (`special_desc`, HTML) as plain paragraphs without the Characters list after it; tags as shown, cast names left out, its themes last; 女频/男频 and the genre slug from tag ids that are the same in every language; an unknown genre id is logged and left empty.
- `theater-stardusttv.ts` — StardustTV's page (`__NUXT_DATA__`, read one devalue index at a time): the labels below level 1 as tags, level 1 as 女频/男频, the first level-2 label as the genre; a page without the drama (an id it lacks, or its own server failing, about 1 in 7 tries on 2026-11-08) is asked for once more, then gives null.
- `theater-moboreels.ts` — MoboReels's series API (the JSON POST its own page makes): its types as tags, its numeric language id, first paid episode; no 频道 or genre.
- `theater-netshort.ts` — NetShort's page (after its redirect to the drama's slug; the app-router stream's `shortPlayDetailVo`): every category the page lists, never one naming the title; the first locked episode; the cover URL encoded.
- `theater-yourchannel.ts` — YourChannel's playlet API: its comma-separated tags, first paid episode or free, the 18-digit id kept a string.
- `theater-dramabox.ts` — DramaBox's page (`__NEXT_DATA__`): its genres then tags, the genre slug, the first locked episode, and 女频/男频 inferred from English genre ids. Built and tested but not called: the site refuses the production server.
- `r2.ts` — SigV4 query presigning for R2 (PUT upload, GET clip, HEAD verify, DELETE), a server-side PUT for a cover copied at import, hour-aligned signed GET URLs browsers can cache for covers and stills, the fixed key of a clip's still, and attachment filenames; the only code that sees the R2 secret.
- `admin.ts` — `TASK_ADMIN_EMAILS` and the one admin check; everyone else gets a 404.
- `route-http.ts` — the shared route guards: task DB, R2 and admin requirements, and the same-origin JSON body read for admin writes.
- `copy.ts` — English and Chinese strings for the public pages (the drama grid with its filters, type, clip-count and 本周爆款 badges and its drama dialog, tasks, a drama's two promo links (推广链接 and 资源推广链接, made as the drama opens; no 口令), the reader's drama page (去看全集, 预告片), clips (系列资源) and how-it-works steps, My Promotions with accounts, My Earnings), the Chinese labels the admin pages use, platform names, the 共 N 集 · 前 M 集免费 line, a clip's title with machine names (UUIDs, hashes) left out, and money, count, size, date and the two promo-link URLs (`promoLink` → `/t/<code>`, `resourceLink` → `/t/<code>/go`).
