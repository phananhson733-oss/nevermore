# apps/marketing/src/lib/task-center

Server code for the task center (short-drama promotion tasks), My Earnings, and the admin backend that uploads clips. Task data lives in TencentDB (`TASKS_DATABASE_URL`), files in a private Cloudflare R2 bucket, sign-in stays on Supabase. With either one unset, every page and route says it is unavailable instead of failing, which is what keeps the Vercel rollback build working. Modules here import each other by relative path so the tests can load them.

- `db.ts` — the lazy `pg` pool (null when `TASKS_DATABASE_URL` is unset), `withTransaction`, and safe bigint-to-number reads.
- `contracts.ts` — claim channels (`all` for new claims), account platforms and statuses, drama statuses, upload types and size limits, the promo code alphabet, and the zod inputs for every admin and claim request.
- `dramas-store.ts` — published listing with filters, search, sort and paging; a drama's detail with its ready assets; the admin reads; create, update, status, cover and asset writes. Replaced cover files are kept in R2, so a retried upload can never leave a drama on a deleted image. Publishing without a promo target is refused, not guessed.
- `claims-store.ts` — idempotent claim of one code per user, drama and channel (new claims are always channel `all`, so one link per drama) (a code collision retries with a new code), a user's links with click counts, and the click-and-redirect for `/t/<code>`; the redirect URL is always built through `URL`, so a target with non-ASCII characters still makes a valid ASCII `Location`.
- `accounts-store.ts` — accounts submitted for whitelisting: submit (a handle already on file returns that row unchanged, so a resubmission never resets a review; at most 20 per person), the promoter's list, withdraw (only while waiting, so a rejection cannot be wiped by deleting and resubmitting), a per-user advisory lock so concurrent submissions cannot pass the cap, the admin list with waiting accounts first, and the review write.
- `earnings-store.ts` — all-or-nothing settlement import (any unknown code rejects the whole file), the import history, and a user's totals per currency and per platform; a figure the platform did not give stays null and shows as "—". Sums come back as decimal strings (`::text`), so they never round or overflow a JS number, each with a flag saying whether some rows in it lacked that figure; the page marks those "partial". A day missing from every file is not detected.
- `settlement-csv.ts` — the settlement CSV: English or Chinese headers, BOM and CRLF, quoted fields, per-line problems, duplicate code+day rows refused; anything that could be read two ways refused too (a row wider than the header even when the overflow is empty, text after a closing quote, two columns meaning the same thing); a 2 MB limit counted in UTF-8 bytes; and amounts converted to minor units by the currency's own exponent without floating point.
- `r2.ts` — SigV4 query presigning for R2 (PUT upload, GET clip, HEAD verify, DELETE), hour-aligned cover URLs browsers can cache, and attachment filenames; the only code that sees the R2 secret.
- `admin.ts` — `TASK_ADMIN_EMAILS` and the one admin check; everyone else gets a 404.
- `route-http.ts` — the shared route guards: task DB, R2 and admin requirements, and the same-origin JSON body read for admin writes.
- `copy.ts` — English and Chinese strings for the public pages (tasks, a drama's link, clips and how-it-works steps, My Promotions with accounts, My Earnings), the Chinese labels the admin pages use, and money, count, date and promo-link formatting.
- `sql-test-harness.ts` — runs `db/tasks/migrate.sh` against a disposable `signalframe_ci*` loopback database for the SQL tests.
- `r2.test.ts`, `settlement-csv.test.ts`, `copy.test.ts` — unit tests: AWS's published SigV4 example; CSV parsing, the refusals of anything ambiguous, minor units and the admin email list; exact money and count formatting past `Number.MAX_SAFE_INTEGER`.
- `task-center.integration.test.ts` — the `marketing-sql` project: migration runner, listing, publishing, assets, claims (per channel and `all`), clicks, earnings import and promoter accounts against real PostgreSQL.
