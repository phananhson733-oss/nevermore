## 0. 先定下来的事

- **剪辑好的素材：Cloudflare R2，不经过我们的服务器和隧道。** 2026-11-05 用户定的：运营上传现成剪辑好的资源，直接传到 R2。Cloudflare 自助套餐的条款（CDN 一节，2026-09-28 版）要求用付费服务（Developer Platform、Stream 这类）才能经它发视频，经隧道转发不行，R2 属于 Developer Platform。做法：服务端发一个有时效的上传地址，浏览器直接 PUT 到 R2；推广者预览、下载也走有时效的地址，直接从 R2 取。R2 单次上传上限约 5 GB，一个剪辑几十 MB，不需要分片，也碰不到隧道单请求 100 MB 的限制。桶私有，只给一个限定在这个桶上的 R2 API 令牌；桶上要配 CORS，允许 gengrowth.ai 发 PUT。
- **登录：沿用现在的 Google 登录。** 只是这几块数据不放 Supabase。用户在新库里用登录态里的用户 ID 认，不另建账号体系。
- **管理员：邮箱白名单。** `TASK_ADMIN_EMAILS` 里列的邮箱登录后能进后台，别的人进不去，接口返回 404。
- **只跑一个实例**，和营销站现在一样。

## 1. 范围

做：

- 顶部导航加「任务中心」`/tasks` 和「我的收益」`/earnings`。
- 任务列表：按平台、语言筛选，按剧名搜索，排序有最新上架、推广人数，分页。
- 任务详情：剧集信息、简介、目录（按集数和收费起始集显示，后面的带锁）、运营上传的剪辑素材，可以预览、下载。
- 四个推广按钮（TikTok、Facebook、Instagram、YouTube）：没登录先弹 Google 登录；登录后领取，生成这个人、这部剧、这个渠道专属的推广链接和口令码，可以复制，同时记进「我的任务」。
- 我的收益：要登录，不让搜索引擎收录。汇总卡片和按平台的收益表，数字来自管理员导入的结算数据，没有导入时显示「—」，不显示 0。
- 管理员后台 `/admin/tasks`：新建、编辑、上下架短剧；上传封面和剪辑好的素材；导入结算数据。后台只有中文。

做的时候另外定的：

- 任务列表、详情、我的收益、后台都不让搜索引擎收录（`noindex`），也不进 sitemap。
- 素材只给登录的人看、下载；封面谁都能看。视频单个不超过 4 GB，图片不超过 20 MB，类型限 MP4、MOV、WebM 和 JPG、PNG、WebP。浏览器传完以后服务端去 R2 核对大小和类型，对上了才对推广者显示。
- 下架的剧从列表里消失，已经发出去的推广链接照常跳转，不让推广者的链接突然失效。
- 结算导入是整份文件全过才算：有一行格式不对，或者有一个推广码不是我们发的，整份不导，把问题行和推广码列出来。同一个推广码同一天再导会覆盖上一次。

不做：邀好友横幅、小说库、提现、收款账户、个税、数据导出。涉及资金的都不做。

## 2. 表（`gengrowth_tasks` 库）

迁移放在 `apps/marketing/db/tasks/`，编号顺序执行，和 `supabase/migrations/` 分开。不进 `packages/db`，那是 `apps/web` 的合同。只用普通 PostgreSQL，属主不是超级用户也能建。

| 表 | 存什么 |
|---|---|
| `dramas` | 一部剧一行：剧名、中文名、平台、语言、集数、收费起始集、简介、封面的 R2 键、上架时间、状态（草稿、上架、下架）、推广目标地址 |
| `drama_assets` | 运营上传的素材一个一行：视频或图片、标题、R2 键、大小、类型、上传状态、排序 |
| `task_claims` | 领取记录：用户 ID、剧、渠道、推广码、领取时间。同一个人、同一部剧、同一个渠道只有一条 |
| `promo_clicks` | 推广链接被点的记录：哪条领取记录、时间。不存访客 IP |
| `earning_imports` | 管理员每次导入一行：谁导的、什么时候、文件名、币种、条数 |
| `earnings` | 导入的明细：日期、哪条领取记录、订单数、广告金额、收益（金额存成这个币种最小单位的整数，美元是分，日元就是元；币种单列）。平台从领取记录对应的剧来。导入里没有的就是没有，存 null，不补 0 |

推广人数从 `task_claims` 数，不是我们编的数字。

## 3. 推广链接

推广链接是 `https://gengrowth.ai/t/<推广码>`：记一次点击，再 302 到这部剧的推广目标地址。目标地址由管理员在后台填，一般是平台给我们分销账号的那条链接；平台支持子渠道参数的话，把推广码带过去，结算时就能按推广码对回到人。短链 `/go/<code>` 在 Supabase 里，这里不复用，任务中心只用自己的库。

## 7. 结算文件

CSV，UTF-8（带不带 BOM 都行），第一行表头，之后每个推广码每天一行：

```csv
date,code,orders,ad_amount,income
2026-11-04,k7m2xq9p,12,30.50,8.25
```

表头也可以写中文：日期、推广码、订单数、广告金额、收益。日期和推广码必填，后三列至少填一列；空着的格子按「平台没给」处理，前台显示「—」。金额按导入时选的币种的常规小数位写。一份最多 20000 行、2 MB。真实的平台结算文件拿到以后再对一次列名，对不上就在导入前转一下，或者在 `settlement-csv.ts` 里加别名。

## 8. 第二期：照 RS Boost 补齐推广者这边（2026-11-06）

用户定的方向：运营只上传自己剪好的素材，这个站是给推广者拿去发 TikTok、Facebook 的，不做从 ReelShort 抓数据自动填。前台照 RS Boost 补四块：

- **一键拿链接。** 详情页不再分四个渠道，只有一个「一键获取推广链接」按钮，点了给这个人、这部剧一条链接和口令码，各平台都用这一条。新领的记成渠道 `all`（迁移 `0002`，只放宽约束，旧镜像照常跑）；以前按渠道领的码继续跳转，在「我的推广」里照样列出来。领取仍然是一次 POST，不是打开页面就生成，免得预取页面就发出码。
- **「我的推广」`/promotions`。** 每条链接：剧名、渠道（新的写「通用」）、点击数、领取时间，链接和口令码都能复制。原来在「我的收益」底下的链接表挪到这里，收益页只放结算数字。三页顶上有同一排标签：任务中心 / 我的推广 / 我的收益。网站顶部导航不加第三个，1280 宽下七个已经刚好放满（第 0 节和 header 注释里量过）。
- **素材下载和使用说明。** 素材按 1、2、3… 编号成按钮，点了直接下载；预览收进「预览素材」折叠里。下面一块「使用说明」四步：下载素材、复制链接、发 TikTok/Facebook 并先报白账号、结算后在「我的收益」看。文案不写分成比例或金额，我们手上没有这个数。
- **账号报白。** 推广者在「我的推广」里提交 TikTok 或 Facebook 账号（@用户名或主页链接），看到「待报白 / 已报白 / 未通过」。一个人最多 20 个；同一个账号再交一次返回原来那条，不会把已经审过的打回待审；还在待报白的可以撤回；运营处理过（通过或拒绝）的不能撤回，否则删掉被拒的再交一次就把拒绝洗掉了。同一个人同时提交几个也不会超过 20 个（按用户加锁）。提交时把登录邮箱一起存下来，运营才知道是谁。后台 `/admin/tasks/accounts` 列出全部，待报白的排前面，点「通过」或「拒绝」，记下是哪个管理员、什么时候点的；点错了可以再点另一个。报白本身要运营自己去平台上做，我们这里只记结果。

## 9. 第三期：素材广场（2026-11-06）

用户看了 MoboBoost 的「素材广场」，要任务中心首页换成一格一格的素材，而不是一部一部的剧。剧的详情页 `/tasks/<id>` 留着。

- **首页 `/tasks` 是素材格子。** 每格一条已上架剧的可用素材，竖版 9:16，左上角是类型（解说、混剪、高光、预告、整集，没标就不显示），中间播放键，下面是剧封面小图、剧名、素材名，再一行「女频 · Romance · 英语」。按最新上架或推广人数排。能按名字搜（剧名、中文名、素材名，`%` 和 `_` 按字面算），按语言、频道（女频/男频）、题材、类型、平台筛。点一格弹窗：登录了就直接播、下载、拿推广链接；没登录给登录入口。草稿和已下架的剧、没传完的素材都不出现。
- **本周爆款。** 最近 7 天领链接的不同人数最多的前 3 部已上架的剧，至少有 1 个人领过；它们的每条素材都挂「本周爆款」。人数一样时最近有人领的排前，再按 id。每次读页面现算，不存表。没人领就一个都不挂，不拿编辑推荐冒充。
- **新字段（迁移 `0003`，只加可空列）。** 剧加「频道」`audience`（female/male）和「题材」`genre`（小写英文 slug，如 romance、werewolf），素材加类型 `clip_type` 和截图 `poster_key`。后台编辑页能填，素材列表每条都能改类型，旧素材补标签不用重传。中文名本来就是可选的，标签上写明了。
- **截图。** 上传视频时浏览器从本地文件里截第 1 秒左右的一帧（最高 960 像素的 JPEG），和视频一起直传 R2 的 `dramas/<id>/posters/<素材id>.jpg`。完成时服务端只认那个固定的 key，HEAD 核对是 JPEG、大小不超过 20 MB 才记上，库里的约束也只允许这条路径，删素材时就不可能删到别的文件；截不出来或传失败只记日志，不影响视频本身可用，格子里就用剧封面（后台页面只在截图真的传上去以后才带 `posterKey`，所以格式不对的 `posterKey` 被 400 拒掉只可能来自手写请求，不会卡住正常上传）。地址里的剧 id 先转小写再拼 key，手敲大写 id 也不会撞上库里的约束。重试完成时不会把已有的截图清掉。删素材连截图一起删。这之前传的素材没有截图，显示剧封面。
- **后台「预览」打不开的修复。** 原来链接是渲染页面时签的，15 分钟就过期，页面开久了点「预览」R2 就报 ExpiredRequest。现在「预览」指向 `/api/admin/tasks/assets/<id>`，点的时候才签一个新的 15 分钟链接再 302 过去，只给管理员、只对已传完的素材。
- **为什么上传了推广者看不到。** 草稿或已下架的剧推广者完全看不到，素材也下不了。后台编辑页现在会写明这一点，没填推广目标地址的还会提示先填再上架。

## 10. 第四期：一步上架，信息从选剧台带出（2026-11-06）

用户嫌上架要填的太多、还分两步。改成只填剧名和平台（语言可选，同一部剧不同语言的名字本来就不一样），其他从选剧台的北斗数据带出。这推翻了第 8 节「不做自动填」那句，但素材照旧是运营自己剪好手动上传，不从北斗下载资源。

- **数据从哪来。** pick-workbench（选剧台）新加一个只读接口 `GET /api/pick/lookup/drama/`，在 web 容器里，和北斗认领共用同一把账号锁，只调 `get_api_fb_task_enum` 和 `get_api_fb_task_page`，从不认领。任务中心走 docker 内网 `http://drama-platform-web-1:8088` 调它，Bearer `PICK_LOOKUP_TOKEN`。接口约定写在 pick-workbench 的 `deploy/lookup-api.md`。同一个查询选剧台缓存十分钟。
- **查剧。** `/admin/tasks` 的新建面板：剧名、平台（选剧台认识的 11 个，或「其他平台」）、语言（默认按剧名自动）、「查剧」。恰好一部同名 → 直接建草稿并跳到它的页面；同名不止一部或只有相近的 → 列出来选「用这部」，或者「都不是，手填」；没查到、其他平台、查剧没配置 → 原来的完整表单，剧名平台语言已带上。北斗里已经建过的那部显示「已建过，去看」，不会建第二份（库里 `(platform, source_drama_id)` 唯一，并发两次也只有一份）。
- **带出来的字段（迁移 `0004`，只加列）。** 集数、收费起始集、简介（优先英文）、标签、是否完结、中文名，加 `source = 'beidou'` 和平台自己的剧 id。北斗不可信的数照选剧台 intake 的规矩处理：dramabox、flareflow 的集数不给，shortmax、moboreels、goodshort 给的是免费集数也不当总集数；超出表约束的集数、收费集记成未知，不硬塞。导入时服务端重新查一次（命中选剧台缓存），只认北斗说的，不收浏览器传回的字段。
- **封面。** 北斗给的是会过期的签名地址，不发给浏览器。导入时服务端下载（只要 https、公网域名、JPEG/PNG/WebP、不超过 20 MB），存到 R2 自己的 `dramas/<id>/covers/` 下。没有封面或拷失败，剧照样建好，页面提示运营手动上传。
- **推广目标地址仍然手填。** 北斗认领是写操作，不在这次范围；没填就不能上架，剧页面上单独一块「推广链接」。
- **详情页。** 后台剧页面顶上一张卡片：封面（下面就是换封面）、平台、语言、集数、收费起始、完结、来源，标签和简介；下面推广链接、推广素材，完整的编辑表单折在最后。前台剧详情页和素材广场弹窗也显示标签。
- **超时。** 北斗排队时一次查剧可能要几十秒。网站在 Cloudflare 后面，它 100 秒就断，所以任务中心等选剧台最多 90 秒，超了提示「选剧台还在查，稍等再点一次」，那时结果多半已经进了选剧台的缓存。导入那一步先建剧再拷封面，万一选剧台缓存已过期、加上拷封面超过 100 秒，剧其实已经建好：再点一次「用这部」会跳到那部剧。这时别点「改成手填」，手填的剧没有北斗 id，挡不住重复。
- **要上线需要：** pick-workbench 发 web 并设 `PICK_LOOKUP_TOKEN`；`marketing.env` 加 `PICK_LOOKUP_URL` 和同一个 `PICK_LOOKUP_TOKEN`。没配时查剧面板直接给手填表单，不报错。

## 11. 第五期：ReelShort 的资料按它官网的原样（2026-11-08）

用户看了查剧建出来的剧：标签、频道、题材、中文名都是空的，说资料的来源应该是剧场本身（比如 ReelShort），尤其是标签。查下来是北斗这部剧的 `tag` 和 `title_ch` 本来就是空的，北斗也根本没有频道和题材。用户定了：先做 ReelShort，其他平台暂时照旧用北斗；标签照官网原样（剧是什么语言就是什么语言的标签，不翻译）。

- **怎么读。** 北斗照旧负责按剧名找到剧和它在平台上的 id；导入时服务端再去 `https://www.reelshort.com/movie/x-<id>` 读这部剧的官网页面（页面里 `__NEXT_DATA__` 的 `props.pageProps.data`）。旧 id 会被 ReelShort 301 到现在那部剧，只跟着 ReelShort 自己的 https 域名走，最多三跳；只收 text/html、不超过 2 MB，15 秒读不到就算了，不抛错。
- **官网压过北斗，逐个字段。** 剧名、集数、收费起始集（官网说全免费就是没有收费集）、简介、标签、频道、题材、封面用官网的；官网没给的那一项退回北斗的。中文名和是否完结只有北斗有。语言仍然是运营选的优先，其次北斗，最后才用官网页面的语言（且必须是查剧认识的语言）。
- **标签。** 官网 `tag_list` 里的标签按页面顺序原样收，最后接上页面的主题 `tag`；分类 1000（女性向/男性向/LGBTQ/全部）不算标签，去填频道；1001、1005 是演员名，不收。去重、每个最长 40 字、最多 20 个，和北斗的标签一样处理。
- **频道和题材按标签 id，不按文字。** 同一个标签在各语言页面上 id 一样（`…663` 英文是 Female，西语是 Mujer），所以 `…663` → female、`…664` → male，LGBTQ 和「全部」留空。题材是分类 1010，2026-11-08 抽了 130 个英文页面只见过六个：comedy、fantasy、sports、romance、drama、animation；没见过的 id 记日志、题材留空，不猜。
- **一部剧只建一次。** 北斗有时一部剧有两个 id（这次的「Lazos rotos de los hermanos fae」就是），两个 id 的官网页面都落到同一部。现在存的是官网落到的那个 id，用另一个 id 再导入会得到「已建过」并跳到第一部。之前建的剧存的还是北斗的 id。
- **读不到官网时。** 剧照样按北斗的资料建好，页面提示「ReelShort 官网这次没读到……标签、频道和题材可能不全，请核对」。读到了则提示「已按 ReelShort 官网的资料建好草稿」。后台剧页面的「来源」对 ReelShort 剧直接链到它的官网页面。
- **已经建好的剧不会自己变。** 这次之前建的那部「Lazos rotos…」字段还是空的，要么手动补，要么删了重新查剧。
- **以后。** 其他平台的官网读法见 §12；查剧候选里同一部剧出现两次（北斗的两个 id）的合并还没做。

## 12. 第六期：其余剧场也按官网读（2026-11-08）

用户要把剩下的平台补齐。逐个查了 10 个平台的官网（ReelShort 以外），能读的按 ReelShort 的方式接上：北斗照旧找剧和 id，导入时服务端再读剧场自己的站，官网有的字段逐个压过北斗。每个站都只走它自己的 https 域名、只收预期的类型、2 MB 以内、15 秒，读不到就退回北斗，不抛错。查不到这部剧时有三个站照样回 200，所以每个读法都核对页面上的 id 等于要查的 id，对不上就当没读到。下面都是 2026-11-08 从生产服务器（Virginia）实测的结果，西语剧也试过，标签是剧本身的语言。

| 平台 | 怎么读 | 标签 | 频道 | 题材 | 收费起始 |
|---|---|---|---|---|---|
| ReelShort | 官网页面 `__NEXT_DATA__` | 页面标签（§11） | 有（标签 id） | 有（标签 id） | 有，或明说全免费 |
| StardustTV | 官网页面 `/episodes/01-x-<id>` 的 `__NUXT_DATA__` | `labels` 第 2 级及以下 | 有（第 1 级：男频/女频） | 第 2 级第一个，转成 slug | 有，或明说全免费 |
| MoboReels | 官网页面背后的接口 `videoapi-hk.cdreader.com/…/homeSeriesDetail`（POST JSON） | 它的分类 `typeItemVOList` | 无 | 无（分类里题材和桥段混在一起，不挑） | 有；没写不当免费 |
| NetShort | 官网页面（会 301 到剧名 slug）里 app-router 流的 `shortPlayDetailVo` | 页面简介句「Movies in …」里的全部分类，没有这句时用 `shortPlayLabels` | 无 | 无 | 第一个上锁的集；都没锁不当免费 |
| YourChannel | 官网播放页背后的接口 `/yourchannel/app/playlet/v4/<id>` | `tags` | 无 | 无 | 有；没有收费集就是全免费（播放器就这么处理） |

- **DramaBox：只给链接，不读。** 读法做好了也测过（`theater-dramabox.ts`：题材 `typeTwoList` 和标签、第一个上锁的集；英文剧按题材 id 推频道，表是从它自己的题材列表抽 183 部得来的，各语言 id 不同所以只对英文），但它的 CloudFront 对我们生产服务器的地址一律 403，换什么 User-Agent 都一样，本机访问是 200。不绕过它的拦截，所以 DramaBox 仍用北斗的资料，后台剧页面给一个它官网页面的链接。哪天不拦了，在 `theater-details.ts` 里把它的 `read` 加回去即可。
- **KalosTV、FlareFlow：读不了。** 两个站的剧情资料只走加密、签名的接口（要访客 token），页面本身没有剧的资料。
- **ShortMax、FlickReels：北斗里没有剧。** 连「Love」都查不到，读官网也无从谈起；shortmax.com 现在还跳到 shorttv.live。
- **GoodShort：现在查剧是坏的，另做。** 北斗给它的 id 是 base64（如 `157KwomEt0CA6EFVXKKgcQ==`），既不是官网用的 id，也过不了查剧对 id 的格式检查和 0004 的约束，所以 GoodShort 的结果全被丢掉，后台一条都看不到。要修得放宽 id（迁移）、改用官网按剧名搜（同名会有两部，要定怎么挑），单独做。
- **语言。** 各站的语言码统一成查剧用的写法（`en_US`、`en-US` → `en`，繁体中文 → `zh-TW`），MoboReels 是数字语言 id，按它站上的语言菜单对。
- **后台。** 查剧时只对能读的五个平台显示「读 X 官网」；读不到时提示官网没读到。剧页面「来源」写「查剧 · X 官网页面 ↗」（DramaBox 也有链接），不再把链接本身写成来源，因为读不到官网时资料其实来自北斗。
