## Architecture

1. **One website asset, additive GEO extension.** Website Profile remains the product-fact authority. A GEO extension is linked by server-proved account/site and exact confirmed Profile reference. Show inherited product name, positioning and features read-only; GEO owns names used for matching, category/market selection, confirmed competitors, role evidence and verified-fact references. Preserve all existing KB/snapshot rows. Never silently merge, delete, relabel or rewrite historical snapshots.
2. **Additive immutable context.** Keep the v1 KB payload/snapshot hash contract readable. Enrichment receipts and a versioned immutable snapshot-context record bind Profile reference, role query evidence, competitor parsing, fact provenance, skipped layers and prompt-set identity to the exact snapshot. Any new database routine must atomically bind its context with freeze, owner-scoped and append-only. Client source labels are not evidence: server reads/signatures prove receipt provenance, while manual edits are explicitly user supplied.
3. **GSC and public enrichment.** Reuse existing verified account/Google subject equality and grant checks. The window is explicitly 90 days, not the Keyword tool's 28-day helper. Group actual queries with bounded deterministic clusters; show their IDs/count/window and distinguish HTML inference/manual roles. With no usable GSC, show the missing source and skip unsupported role-derived layers rather than fabricating roles. Competitor homepage extraction keeps safe fetch URL/time/status and manual-confirmation fallback.
4. **Measurement and gaps.** Support explicit engine selection and capabilities. Per-engine sample IDs include engine/question/index; aggregate same-version metrics with explicit denominators. Add confirmed-brand co-mention share, list-position only where actual ranked-list structure supports it, cited-answer counts, reference-page types and independently read own-presence. A/B/C/D are evidence-conditioned gap classifications, not causal attribution of business outcomes. Missing index/T2/measurement evidence remains unattributed with a reason. C produces third-party work, never a content-draft action.
5. **Actual bounded rendering.** T2 stays anonymous URL+optional question, deterministic, no LLM. A server adapter obtains raw/rendered body evidence from an isolated rendering service; every page/subresource request uses public URL/DNS/IP/redirect checks and bounded fetch, with no cookies, credentials, arbitrary sockets or unbounded work. A real local Chromium fixture proves JS rendering; a typed runtime failure is different from an absent implementation. Root-cause groups derive from rule dependencies, not model prose. Existing rule validity/unknown/notApplicable protections stay intact.
6. **Shared content contract.** Add an explicitly versioned GEO branch (`gengrowth.content_brief/v1.1`) to the common Brief/Draft package, retaining exact v1 SEO parsing. Common consumers use a discriminated source adapter, not fake SERP/GSC ledgers. The GEO branch carries `geo_origin, lead_answer, must_answer, fact_table, outline, format, length, verdict, internal_links, budget, draft_readiness` and a deterministic fingerprint. lead_answer is a frozen KB requirement included in Q1. AI sample topics carry sample evidence/coverage, never factual sentence authority. Format derives from gap/layer (D comparison, A intent), length is honestly unavailable without relevant observations, links come from a real site index.
7. **One Draft tool.** Reuse the current Draft route/UI/generation and coverage engine. Extend sentence evidence/source handling for verified KB facts, keep null-valued facts unusable, and deterministically derive source labels. Both SEO and GEO use the same existing fixed-key/TTL/single-use handoff mechanism. GEO outputs route to Citability; SEO stays On-Page. Display, JSON, Markdown and handoff retain the same origin/version/source fields.
8. **Compatibility and controls.** Historical v1 outputs remain readable under their own contracts. Imported run files are validated data, never authenticated server evidence. No automatic paid POST retry. Distinguish query/question/sample units. Rendered ratios require actual two-sided measurements. No aggregate success inferred from partial data or source failures.
