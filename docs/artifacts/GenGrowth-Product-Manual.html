01 · Product definition

产品定义与优势：不是另一份审计报告

GenGrowth 把产品与 ICP、网站和市场证据、可审核的问题、增长机会、客户可见交付物以及固定窗口结果，组织在同一条可追溯链路中。

客户看到的不只是“发现了什么”，还包括“为什么、影响哪些 URL、要交付什么、谁来批准、动作是否发生、结果是否被独立复查”。

一站式机会地图

URL、Topic Cluster、Keyword、Competitor、Finding 与 Opportunity 互相映射；多 URL 和模板级机会是常态，不被压成单页卡片。

Cluster-first 内容策略

关键词先进入主题簇，再决定现有页面、新资产、页面角色和 CTA；避免“一词一文”的内容工厂。

治理与可追溯版本

Artifact Revision、Quality Gates、人工批准、批准失效、模拟 Release、Rollback Ref 和 Audit Event 使用同一对象链。

诚实的结果边界

Receipt 证明动作，Technical Verification 证明可复查技术条件，Observation 记录固定窗口变化；三者不会被混成虚假因果。

URL 详情与页面证据如何工作

Competitor 参与正式分析的规则

Revision、Quality Gates、Approval 与 Release

  • Artifact 保存 Title、Type、Owner、Opportunity、Target URLs、Evidence、Required Gates、Passed Gates 与当前 Revision。
  • Readiness = Passed Gates ÷ Required Gates；Research、SEO、GEO、Factual、Human、Technical、Tracking、Publish、Legal 按类型组合。
  • 只有 status=review 且全部非 Human Gate 通过时才能批准；批准会补 Human Gate。

07 · Results

效果追踪：改前、改后与归因边界

正常的增长交付不应只展示“现在有多少”。当前 Results 使用固定 Baseline / Current 窗口，分开呈现 Technical Verification、Page Observation、Campaign / UTM 与动作回执。

Technical Verification

可复查技术条件

旧值、新值、验收值和 Verified / Not Resolved / Unavailable；例如 canonical 是否唯一、结构化步骤是否完整。

Page Observation

固定窗口相关变化

自然搜索点击、转化、AI Citation 等 Before / Current；Observed 只表示同一窗口记录到变化，不代表单一 Artifact 因果。

Campaign / UTM

分发与转化路径

Source、Medium、Campaign、Content、Landing URL、Sessions、Direct 与 Assisted Conversion，同时保留归因限制。

Receipt 证明动作发生；Technical Verification 证明技术条件；Observation 记录固定窗口变化。三者不是同一个对象，也不能互相替代。

结果状态的诚实语义

  • Verified：复查条件满足，例如期望值与当前值一致。
  • Not Resolved：动作可能发生，但技术验收仍未达标。
  • Observed：固定窗口观察到变化，不宣称因果。
  • Insufficient：样本或 Campaign 组合不足以支持结论。
  • Unavailable：目标变更未进入可复查部署快照或来源不可用。
Presenter card · 90 sec

“发布回执不是增长结果。”

画面证据
技术复查三态、结果边界卡、动作回执与效果事件双时间线。
优势
把“做过什么”和“发生什么变化”分开，避免为了看起来成功而制造即时增长数字。
限制
没有对照实验或更强归因证据时，不把单一 Artifact 写成全部增量原因。

数据连接：客户只看到 GSC、GA4 与 GitHub

Sitemap、Crawl、SERP、AI Answers、Profile、客户访谈、竞品语料与 CMS 场景回执是系统证据，不在连接管理里伪装成客户要配置的 Provider。

场景可用

Google Search Console

支撑 Query、Landing Page、Rank、Search Observation 与 URL 映射；当前 externalConnection=false。

场景可用

Google Analytics 4

支撑 Page、Campaign / UTM 与 Conversion Observation；当前不会读取真实客户账号。

待接入

GitHub

预留 Branch → PR → Human Review → Merge → Rollback Receipt 流程；当前 connectionState=unavailable。

Source Freshness 规则

status=unavailable 或没有 observedAt → Unavailable；Age ≤ SLA → Fresh；SLA < Age ≤ 2×SLA → Aging；Age > 2×SLA → Stale。对象引用多个来源时，当前 UI 显示最旧有效来源观察时间，避免只展示最新来源掩盖陈旧证据。

缺失值诚实规则

null 不是 0。Volume 缺失显示“未连接”，KD 缺失显示“不可用”，Rank 缺失显示“未覆盖”；真实数值 0 仍保留为 0。手工新增 Keyword / Competitor 的外部指标为空，不能翻译成“没有流量”或“没有 AI 引用”。

10 · Object model & lifecycle

对象模型与生命周期：从事实到交付再到结果

Diagnosis、WebTech、Acquisition、Landing 是 Finding / Opportunity 的 Lens，不是四套 Project、四套状态机或四套交付对象。

Finding

可审核的问题事实

包含 ruleId、Lens、Severity、Status、URL、Source 与 Evidence。确认或排除会留下客户审核记录。

Opportunity

面向执行的决策聚合

聚合一个或多个 Finding、一个或多个 URL、Priority、限制和 Artifact。当前主要 Finding 是 findingIds[0] 的 UI 约定。

Artifact

客户可见的交付物

保存正文、Type、Owner、Target URLs、Evidence、Required Gates、Passed Gates、Revision、Approval 与 Release 关系。

Delivered / Observing / Closed 存在于场景数据，
但当前 Publish 不会自动推进完整 Opportunity 状态链。
Artifact 与 Revision
Review
├─ 非 Human Gate 未完成 → Approval Blocked
└─ 非 Human Gate 完成 + 人工批准 → Approved
   └─ 全部 Gate 完成 + Simulated Publish
      → Published + Release Receipt + Rollback Ref

任意可编辑 Artifact
└─ New Revision → Review
   ├─ Human Gate 移除
   ├─ 旧 Approval 失效
   └─ 历史 Revision / Release 保留
Competitor
Manual Add → Candidate
Candidate + Review
├─ Approved + Non-excluded Scope → 参与正式分析
├─ Candidate → 保留但不参与
└─ Excluded → 强制 Excluded Scope，历史证据保留
底层规则速查

开放机会：closed 与 dismissed 不计入开放机会。Priority 按 P0 → P1 → P2；同优先级按状态、Finding 数与标题排序。

画像完整度：从十类核心上下文是否存在计算，不是字段置信度均值。

Readiness：Passed Gates ÷ Required Gates × 100。

Results：页面 KPI 聚合 pageObservations；百分比为 (current-before)/before；before=0 且 current>0 显示“新增”；Tagged UTM 只聚合 campaign 非空记录。

当前 Artifact 已形成可演示闭环，但外部连接、生产持久化与部分 canonical object contract 仍是后续范围。

  • 字段 provenance 与 append-only Profile Version。
  • URL / Cluster / Keyword / Competitor / Opportunity read model。

15 · FAQ & source registry

FAQ、讲解口径与来源登记

以下问题可以直接用于购买方问答；答案只描述当前 Artifact，生产安全、DPA、真实 Provider 与后端架构需要独立材料。

这是实时产品吗？

当前文件是离线确定性场景 Artifact。数据来自内置 RelayOps 快照，不连接真实 GSC、GA4、CMS、GitHub 或第三方 Provider。它用于验证产品信息架构、对象闭环、客户审核与真实性边界。

GSC / GA4 为什么显示可用？

“可用”表示当前场景快照可用于分析演示，不等于 OAuth 已连接。更新分析数据只修改当前会话 observedAt、重算摘要并写同步 Audit Event。

GitHub 能自动创建 PR 吗？

当前不能。界面保留了 Branch → PR → Review → Merge → Rollback Receipt 的计划流程，connectionState 明确为 unavailable。

为什么 Keyword 不直接生成文章？

因为 Keyword 是发现与衡量单位，Page 是交付单位，Topic Cluster 是执行与经营单位。平台先决定主题、现有 / 新页面、页面角色和 CTA，再形成 Opportunity 与 Artifact。

候选竞品会影响正式分析吗？

不会。只有 Approved 且分析范围不是 Excluded 的竞品才进入正式 Gap 与比较。Candidate 可以保留发现证据，等待客户审核。

为什么修改 Artifact 后必须重新批准？

Approval 绑定精确 Revision。客户可见正文、实现说明或验收范围变化后，旧 Approval 不能自动延续；历史 Revision 和 Release 仍作为只读审计记录保留。

模拟分享或发布会修改客户网站吗？

不会。分享只生成不可外部访问的 local-artifact:// 地址；发布只在浏览器内存创建 simulated Release、Rollback Ref 与 Audit Event。不会发邮件，也没有真实外部写入。

结果增长能归因于某个 Artifact 吗？
